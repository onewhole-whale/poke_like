## 1. 版本目标

实现 M2-C **图鉴收集进度**：精灵图鉴独立成玩家视角 tab，带总收集率进度条 + 分属性系收集完成度 + 里程碑奖励领取，形成"收集 → 解锁奖励 → 驱动继续收集"的闭环。

与计划文档 §M2-C（206 行）逐条对应：

| 需求条目 | 本版本落地 |
|---|---|
| 图鉴 tab 拆分：精灵图鉴独立成 tab | 新增玩家视角「图鉴」tab（`#/dex`）；现有管理端「图鉴编辑」tab 改名保留（见 §11-Q4 待确认） |
| 收集率进度条 | 顶部总进度条 X/N + 百分比 |
| 种族图鉴完成度奖励 | 分属性系 15 系：每系收集满 → 解锁该系奖励；总收集里程碑：5 档阈值奖励 |
| 图鉴 = 核心驱动力闭环 | 奖励为灵息结晶/素材/洗髓露/元素萌芽等已有资源，领取即入库存 |

**范围边界**：只做收集进度 + 奖励领取。不做：立绘/形象展示位（M3 精灵形象范畴）、收集率对游戏玩法的数值加成（如全收集 buff）、PvP/分享功能。

## 3. 设计方案（待用户确认后定稿）

### 3.1 数据结构

新增存档字段（localStorage 自动持久化，旧存档读取时缺省为空对象/数组，不报错）：

```js
S.dexSeen = { firewolf:true, firewolf_e:true, ... };   // 曾"拥有/捕获/进化"过的物种 id
S.dexClaimed = ['milestone_10','elem_fire','...'];       // 已领取的奖励 id（防重复领）
```

**收集时点埋点**（写 S.dexSeen[id]=true）：
- `landSpirit()` 灵兽入仓时（含飞升承接）
- `makeBeast()` 妖兽捕获时（野外遇到即算"见过"——见 §11-Q1）
- `evolveSpirit()` 进化到新物种时
- 初始存档：把 init() 里 push 的初始灵兽/妖兽 speciesId 预填进 dexSeen（炎狼/水狐/雷枭/赤羽雀）

### 3.2 收集判定（§11-Q1 待确认，以下为建议方案）

- **点亮 = 曾拥有/曾捕获**：写过 dexSeen 即点亮，后续放生/炼化不熄灭。
- **进化形态独立计格**：炎狼、炽焰狼王、炎狼王 = 三个独立图鉴格。理由：进化链本身是收集驱动力。
- **DUNGEON_SPECIALS（副本专供 13 只）不计入收集分母**：它们是副本敌人、不可被玩家获得，放进收集进度会污染百分比。建议在图鉴页单列"秘境遭遇"区展示（灰名、不可收集），或干脆不显示。
- **异色不单列格位**（§11-Q2 待确认）：异色在已有格位上显示"✦"标记，不计入完成度分母。

### 3.3 收集率计算

```js
function dexProgress(){
  const all = allSpecies();                          // SPECIES + customSpecies（不含 DUNGEON_SPECIALS）
  const owned = all.filter(sp => S.dexSeen[sp.id]);
  return { total: all.length, owned: owned.length, pct: owned.length/all.length };
}
function elemDexProgress(elem){
  const list = allSpecies().filter(sp=>sp.elem===elem);
  const owned = list.filter(sp=>S.dexSeen[sp.id]);

}
```

## 4. 实现方案（分模块）

### 4.1 数据层

1. `S` 初始定义加 `dexSeen:{}`、`dexClaimed:[]`。
2. 新增函数（放 allSpecies 附近）：
   - `dexProgress()` / `elemDexProgress(elem)`
   - `dexRewards`：奖励定义表（常量，含 id/条件/奖励/描述）
   - `dexRewardState(rw)`：返回 {claimed, met}
   - `claimDexReward(rwId)`：校验 + 发奖 + 写 claimed
   - `markDexSeen(speciesId)`：写 dexSeen（幂等）
3. 埋点：`landSpirit` / `makeBeast` / `evolveSpirit` 末尾调 `markDexSeen`。
4. 初始存档：init() 里把初始灵兽/妖兽 speciesId 预填 dexSeen。

### 4.2 玩家图鉴 tab

1. 路由白名单加 `'dex'`；导航加按钮「图鉴」；现有「图鉴」按钮文字改「图鉴编辑」。
2. 新增 `<section class="view" id="view-dex">` 容器。
3. 新增 `renderDex()`：渲染顶部进度 + 里程碑区 + 分系区 + 精灵格网。
4. `render()` 函数里加 `case 'dex': renderDex(); break;`（需先看 render() 怎么分发）。

### 4.3 奖励领取

- 里程碑卡片：`{met ? (claimed?'已领取':'[领取]') : '未达成'}`

### 4.4 不改动

- 现有 view-codex（图鉴编辑）本体不动，仅改导航按钮文字。
- 不重构 renderCodex。
- 不改 SPECIES 数据。

## 5. 执行流程

```
捕获妖兽/炼化灵兽/进化 → markDexSeen(speciesId) → S.dexSeen[id]=true → saveDraft
玩家点「图鉴」tab → renderDex()
  → dexProgress() 算总进度 → 进度条 X/66
  → 遍历 MILESTONE_REWARDS → 每档算 met/claimed → 卡片
  → 遍历 15 elem → elemDexProgress → 每系格子 + 系奖励按钮
  → 遍历 allSpecies() 按 elem 分组 → 收集格网
点「领取」→ claimDexReward(id)
  → 校验未领 + met → 发奖入库存 → S.dexClaimed.push(id) → saveDraft → toast → renderDex
```

## 11. 待用户确认的 4 项口径（确认前不动代码）

### Q1. 收集判定：点亮 = 见过还是拥有？进化形态是否单独计格？

**建议方案**：
- 点亮 = **曾拥有/曾捕获**（写过 dexSeen 即点亮，放生/炼化不熄灭）。妖兽野外捕获也算点亮。
- **进化形态独立计格**：normal/elite/perfect 三形态各算一格（66 只 = 21 链×3 + 3 传说）。
- DUNGEON_SPECIALS（13 只副本专供）**不计入收集分母**（不可获得），图鉴页单列"秘境遭遇"灰名区或不显示。

**请确认**：
- (a) 妖兽捕获是否点亮？还是只有灵兽（炼化/飞升）才点亮？
- (b) 进化形态独立计格 OK？还是只记"物种种族"（炎狼一系算一格）？
- (c) 副本专供 13 只怎么处理？

### Q2. 异色是否单列收集格位？

**建议方案**：**不单列**。异色在已有格位右上角显示"✦"标记（类似宝可梦闪光图鉴），不计入完成度分母。异色 3% 概率极低，单列会让 100% 变得极肝。

**请确认**：接受异色标记制？还是要异色单列一格（难度大幅提升）？
