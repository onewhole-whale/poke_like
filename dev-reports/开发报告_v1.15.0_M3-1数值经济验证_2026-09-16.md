## 3. 实现方案

### 3.1 受击回能 +1（最小改动）

- `beastTurn`（野外）与 `dgBeastTurn`（秘境）：敌方攻击动作结算后，若该动作是敌方主动攻击（非 tickStatus/非受击反击），`b.energy = Math.min(b.energyMax||20, b.energy+1)`。
- 判定点：敌方成功出手（技能/普攻结算后，未被 miss/未被 guard 完全抵消仍算"敌方攻击动作"——按需求"攻击动作结算后"，只要敌方出手就 +1，不看我方是否掉血）。
- 上限 20 不变；多段只 +1（按"动作"不按"段"）；妖兽（我方受击方）不参与。
- reg_cdp/mech_test/damage_accept 回归。

### 3.2 炼化 120 次硬保底

- S 初始加 `refineFate:{}`（旧档缺省 {} 兼容）。
- doRefine 候选池非空时：池中每只 speciesId `S.refineFate[sp]=(S.refineFate[sp]||0)+1`；池空不涨。
- 出率：fate<120（demo<60）恒 1%；fate≥120（demo≥60）必出。
- 选种：必出时若池中某只 fate≥阈值 → 直接出该只（多只按品质权重 0.1^rank）；否则走现有 pickSpiritByRarity。
- 出后：`delete S.refineFate[被出的speciesId]`（只清该只，池中其他保留）。
- saveDraft 持久化 refineFate。
- UI：炼化候选池每只显示「缘分 X/120」；逼近阈值（≥100）金色提示。
- 自然 1% 出后也清 fate？——按需求"出后只清被出的那只"，自然 1% 出也清。

### 3.3 秘境沙盒走格子（替换 wild 线性 nodes）

- **数据层**：
  - `TERRAIN`：地块基类表 {id,name,size:1, plant:[a,b], ore:[c,d], qualityDist:{normal:…,fine:…,legend:…}, matList:[matId…]}。本期做 4-6 个示例地形（平原/林地/矿脉/水域/岩地/秘境核心）。
  - `EVENTS`：事件基类表 {id,name,kind:'fight'|'wonder'|'adventure', difficulty, enemyPool, buffRule, templateProb}。本期 fight 事件复用现有野生妖兽池；wonder 沿用现有 WONDERS。
  - `MAP_CONFIGS`：地图配置 {id,name,size:7, terrainWeights, eventWeights, overrides}。本期做 1 张 7×7 中图（替换现有"出发探索"）。
- **S.wild 重构**：state:'idle'→'grid'；grid={size, cells:[[{terrain,event,explored,looted,x,y}...]], px,py, exitX,exitY, loots:[]}。
- **生成**：按 terrainWeights 铺地形图 → 随机选 ~50% 格撒事件 → 随机选出口（非起点）→ 起点固定角落。
- **渲染**：7×7 网格 CSS；未探索格黑雾（？）；已探索格显示地形图标/资源量；事件格显示感叹号；出口格金色标记（即使未探索也可见——按需求"出口格唯一且直接可见"）。
- **移动**：点相邻格（上下左右）→ 扣 1 体力 → px,py 移动 → 新格 explored=true → 若格有事件则触发（fight 进战斗/wonder 出选择支）；若格有资源则可采集。
- **到达出口**：结算离开（素材入包、经验入账）；可随时主动撤退（带走已得）。
- **边界**：不可越界。
- **旧线性 nodes 代码**：genWildNodes/renderWildNode/renderWildEvent/renderWildResult/renderWildSummary 标注 deprecated 或删除（本期删除，避免双套）。

### 3.4 体力行动制

- 自然恢复：10min+1 → **6min+1**；上限 staminaMax 改 **120**（原当前值待查，通常 50）。
- 进入冒险：0 体力（原 5）。
- 移动：1 体力/步（在沙盒移动函数里扣）。
- 采集：1 体力/次。
- 事件/战斗：0 体力。
- 副本：10/场+1 灵息结晶（不变）。
- 单登 120/天 ≈ 2 把中图（~60-70 体力）+ 副本 5 场。

### 3.5 采集工具框架

- **TOOL_TREE**：8 细分（木头/花草叶/水生/果实/金属/石料/气体）× 6 品质（normal/good/fine/rare/epic/legend）= 48 种工具数据结构 {id,name,subtype,quality,capacity,durability,yield}。
  - yield: 1/1.5/2/2.5/3/4（×单次采集量）；
  - durability: 100/120/140/160/180/200；
  - 锯变体：yield×2、durability×0.6（本期数据结构预留，不单独建 8 个 id）。
- **S.tools** 重构：从 `S.tools=矿镐计数` 改为 `S.toolInv={toolId:count}`（旧档 S.tools 数字迁移为普通矿镐×N）。
- **采集函数**：collectTile(x,y) 校验（资源量>0/未采空/耐久>0/体力≥1）→ 品质池（≤工具品质）→ 按 qualityDist roll 品质 → 按 matList roll 细分（工具定向优先，无则顶替）→ 平分素材 → 出货 → 资源量-=（1+2×品质档）×yield → 耐久-1 → 体力-1。
- **无工具**：50% 出货率、仅普通品质、仍扣 1 体力。
- **采空**：格子变灰、名称不变。
- **本期 UI**：简化——工具栏显示当前装备工具（默认空手）+ 耐久进度；不做 48 个工具的制作 UI（图纸下版填充）。

### 3.6 敌方模版 + 上位素材

- wildBeast 生成后套模版倍率：roll templateProb（80/15/5）→ normal/elite/boss。
  - normal: 不乘；
  - elite: hp×3, atk/def/spa/sdef×1.5；
  - boss: hp×5, atk/def/spa/sdef×2.5；
  - 速度 spd 不乘。
- 首领（boss）：不触发 ambush（突袭）；战斗中可"逃跑"按钮 → 退回上一格、事件保留、不扣体力。
- 掉落：精英掉落上位素材品质+1，首领+2（封顶 legend）。上位素材 id 命名 `up_{baseMatId}`，本期不真建 48 个上位素材——在掉落函数里按 baseMatId 动态生成"虚拟上位素材"（继承 baseMat 数据+品质+1/+2），入 S.matEdits 持久化。

### 3.7 战斗全程 buff 表

- `BATTLE_BUFFS` 全局表（10 个示例，按需求 §2.9.7 表）：{id,name,effectType:'buff'|'debuff'|'neutral', desc, params}。
- 地图配置 buffRule:{pool:[buffId...], count:N}。
- 实例化：进入战斗时按难度映射 side（简单=buff→我方/debuff→敌方；普通=无或同 buff 双方；困难=buff→敌方/debuff→我方），从 pool 抽 count 个。
- b.battleBuffs = [{id,side,effectType,...}]；回合末 tickBattleBuffs 结算（回血/回能/减伤等）。
- 本期实现 3 个核心 buff：b-regen（回血 12%）、b-energy-5（回能+5）、b-harden（减伤 8%）；其余数据结构预留。

### 3.8 三层架构

- 本期数据量最小化：TERRAIN 6 个、EVENTS 3 类（fight/wonder/adventure）、MAP_CONFIGS 1 张（7×7 中图）。
- 继承语义：mapConfig.overrides[terrainId] 可覆写 qualityDist/resRange/matLists；缺省继承 TERRAIN。
- 实例化：进冒险时生成 grid，资源量 roll、品质 roll、素材 roll 一次定局。

### 3.9 demo 默认 false

- S 初始 demo:false；首启时 toast 提示"演示模式可在右上角手动开启"。
- 现有 mode-switch 按钮（真实/演示）保留。

## 4. 执行流程（关键调用链）

- **进冒险**：renderWild idle → 选区域 → 点"出发探索"（0 体力）→ genSandbox(zone) → grid 生成 → renderWildGrid 渲染 → 等待移动。
- **移动**：点相邻格 → spendStamina(1) → px,py 更新 → explored=true → 触发格上事件（fight→startBattle；wonder→wonder 选择支）→ renderWildGrid。
- **采集**：点已探索有资源格 → collectTile → 校验 → roll → 素材入包 → 资源量扣减 → 格子变灰（若空）→ renderWildGrid。
- **战斗**：fight 事件 → startBattle（含模版 roll + buff 实例化）→ 胜利掉落（含上位素材）→ 事件标记 resolved → renderWildGrid。
- **逃跑**：boss 战斗逃跑按钮 → b.phase='fled' → 退回上一格（事件保留）→ renderWildGrid。
- **到达出口/撤退**：结算 → 素材入包 → renderWildSummary。
- **炼化**：doRefine → 候选池非空 fate+1 → fate≥120 必出 → 出后 delete fate[该只] → saveDraft。
- **受击回能**：beastTurn/dgBeastTurn 敌方出手后 b.energy+1（上限 20）。

## 9. 待用户确认口径（4 项，确认后动手）

1. **沙盒是替换现有 wild 线性冒险，还是新增第三个视图？**
   建议：替换 wild 的"出发探索"流程为走格子（保留区域选择、灵兽选择、战斗结算）；旧 genWildNodes/renderWildNode 等线性代码删除。理由：需求文档把"冒险系统"列为替换项（§2.7#4），双套并存会维护困难。
2. **体力自然恢复从 10min+1 改 6min+1、上限改 120——是直接改全局，还是只对新冒险模式生效？**
   建议：全局改（副本门票制也吃同一池体力）。理由：需求 §2.5 表是全局体力经济。
3. **48 种工具本期做数据结构+采集算法，但不做制作 UI/商店购买——玩家本期怎么获得工具？**
   建议：本期默认空手采集（50% 出货仅普通）；工具获取 UI 下版做。理由：版本边界"内容下版填充"。
4. **上位素材本期动态生成（不建具体 MATS 条目），还是真建 48 个上位素材数据？**
   建议：动态生成函数（getUpMat(baseMatId, qualityBump)），入 S.matEdits 持久化。理由：下版批量命名时再固化 id，本期先验证机制。
