## 1. 版本目标

实现 M2-B **普通进化机制**（捉宠标配式进化，非奇迹进化——奇迹进化属 V2 大版本）。一句话：**精灵达成进化条件后，玩家可在灵兽仓触发进化，进化后切换为进化形态（物种/品级/种族值/速度/技能池更新），且支持网状进化（多对一、一对多）与管理端配置。**

与需求文档（DEVELOPMENT_PLAN.md §M2-B）逐条对应：

| 需求条目 | 本版本落地 |
|---|---|
| 数码宝贝式网状进化：不同精灵满足条件可进化为同一种 | 多对一（evoTo 同目标，数据层已支持） |
| 同一种在不同路线下可进化成不同精灵 | 一对多（需扩展数据结构，见 §5.1） |
| 进化条件多样化：等级 / 特定属性亲和力组合 / 属性值 / 面板属性值阈值，不必全有 | 条件数组 evoCond，见 §5.1 |
| 最多进化 2 次（3 层），不是必须 | 现有链已符合（normal→elite→perfect） |
| 管理端可配置进化分支与条件 | openSpeciesForm 扩展，见 §5.4 |
| 设计新精灵时要带进化链 | 数据已就绪（66 只，21 条链） |
| 验收：图鉴可见进化链与条件；精灵达成条件可进化；进化后种族值/技能池/形象更新；多对一与一对多都成立 | 见 §8 |

**范围边界**：只做"普通进化"。奇迹进化（特殊进化逻辑）、AI 称号、AI 冒险故事均属 V2，本版本不碰。装备系统（M2 挂起）不碰。

## 3. 设计定稿（本版本新增的数据结构与规则）

### 3.1 进化条件字段 `evoCond`

新增可选字段，挂在 SPECIES 物种上（内置数据 + 管理端可配）：

```js
// 单目标（兼容现有单值 evoTo）：
{ id:'firewolf', evoTo:'firewolf_e', evoCond:[
    {type:'lvl', v:30},                  // 等级 ≥ 30
    {type:'aff', elem:'fire', v:60},     // 火属性亲和力 ≥ 60
    {type:'stat', k:'atk', v:200}        // 面板攻击力 ≥ 200（spiritStats 结算后的值）
] }

// 网状多分支（一对多，新增 evoToBranches 支持）：
{ id:'xxx', evoToBranches:[
    {to:'xxx_a', cond:[{type:'lvl', v:30}, {type:'aff', elem:'fire', v:80}]},
    {to:'xxx_b', cond:[{type:'lvl', v:30}, {type:'stat', k:'spd', v:150}]}
] }
```

规则：

1. **条件类型枚举（首版支持）**：`lvl`（等级）、`aff`（某属性亲和力，`elem`+`v`）、`stat`（某面板属性阈值，`k`∈hp/atk/def/spa/sdef/spe，`v`=spiritStats 结算后数值）。后续如需扩展（如战斗场次、技能熟练度），在 `evoCond` 条件判定函数中加分支，数据结构天然可扩。
2. **语义 = AND**：同一条进化路径的条件数组全部满足才可进化；一个条件对象内部就是单条阈值，不需要 OR 语义（首版不做 OR，标注【待确认】，有需求再加 `any` 分组）。
3. **`evoTo` 与 `evoToBranches` 互斥**：有 `evoToBranches` 时忽略 `evoTo`；两者皆无 = 不可进化。
4. **兼容**：现有 21 条链的 `evoTo` 单值全部保留，仅补 `evoCond`（首版默认配 `[{type:'lvl', v:30}]` 级别的简单条件，具体数值见 §7 配置建议，开发时可调整，但**必须在开发报告/版本记录中写明最终数值**）。

### 3.2 进化后保留与更新

| 项 | 处理 |
|---|---|
| speciesId / name / elem（如变） | 切换到目标物种（从 SPECIES 读） |
| rarity | 切换到目标物种品级（normal→elite→perfect 由链保证） |
| 种族值 / 速度 | 自动（spiritStats 实时读新物种） |
| 技能池 | **保留已习得/已装备技能**（不删除）；新物种技能池中玩家未习得的技能**自动解锁进 skillPool**（标注【待确认】：或只在下次进技能页时提示解锁，选前者实现简单且不丢养成） |
| 熟练度 / 容量 / 已用容量 | 保留 |
| 个体值 iv / 性格 nature | 保留（个体值字段与性格随精灵实例，与物种无关） |
| 专长 perks / 亲和力 aff | 保留 |
| 异色 shiny / 来源 source | 保留；**进化日志追加** `进化：炎狼 → 炽焰狼王` 到 `s.log` |
| 等级 lvl / exp / bonusLv | 保留 |

### 3.3 谁可以进化

- **灵兽（S.spirits）**：可进化。
- **妖兽（S.beasts）**：**不可进化**（默认方案，标注【待确认】）。理由：妖兽定位是"资质随机、无专长之途"的兼容玩法 + 飞升材料，进化是培养体系的一部分；妖兽想变强走"飞升承接"（进化是灵兽侧能力）。如用户后续允许妖兽进化，再放开入口。

### 3.4 飞升承接上游校验（联动本版本）

需求定稿（A2b）：承接目标是 **elite/perfect 灵兽** 时，只能用**进化链上游可达形态**的妖兽承接。实现：

- 新增辅助函数 `isEvoAncestor(targetSpeciesId, beastSpeciesId)`：从 target 沿 `evoTo`（含 evoToBranches 的 `to`）反向回溯，判断 beast 是否在 target 的进化源链上（含 target 自身？——不含：妖兽不能是目标自身形态，必须来自上游，**标注【待确认】**）。
- 在 `landSpirit` 承接分支校验：不满足时拒绝并 toast 提示"该妖兽形态无法承接目标灵兽（需进化链上游形态）"。
- **注意**：飞升校验逻辑若改动 landSpirit 会影响现有承接流程，开发时先读 3200 行完整实现再小改，避免破坏普通/传说承接。

## 4. 实现方案（分模块）

### 4.1 数据层

1. SPECIES 内置数据：为 21 条链补 `evoCond`（§7 配置建议）。**不修改 evoTo 结构与现有字段。**
2. 新增条件判定函数（放 spiritStats 附近）：

```js
function evoCondOk(spirit, condList){ /* 全部 AND 满足返回 true，否则 false */ }
function evoCondText(condList){ /* 渲染成人类可读文案，如"Lv≥30 · 火亲和≥60" */ }
function evoBranchesOf(sp){ /* 归一化：返回 [{to, cond}]，兼容 evoTo 单值与 evoToBranches */ }
function canEvolve(spirit){ /* 返回 [{to, cond, ok}] 或 null */ }
```

3. `allSpeciesDef` / `speciesBase` 不需要改（物种数据已含新字段，自然透传）。

### 4.2 玩家侧入口与结算

1. `spiritCard(s)` 卡片（或精灵详情弹窗）：有可进化分支时显示**「进化」按钮**（每分支一个，或点进化 → 弹窗选分支）。条件未满足时按钮置灰（disabled）+ 悬浮/文字显示缺失条件（用 `evoCondText` + 当前值对比）。
2. 新增 `evolveSpirit(spirit, targetSpeciesId)`：
   - 校验 `canEvolve` 仍成立（防穿透）；
   - 写 `speciesId/name`（若目标 elem 不同也更新）；
   - 解锁新物种技能池技能进 skillPool；
   - 追加 log；toast 进化成功；重渲染灵兽仓 + 图鉴收集进度（若 C 已实现）；
   - 返回新面板摘要用于确认弹窗预览（进化前展示：目标形态/品级/种族值对比/条件满足情况）。
3. 确认弹窗（复用现有 `#overlay/#modal-box` 模式，参照 openSpeciesForm 的弹窗写法）：显示"炎狼 → 炽焰狼王（精英）"+ 种族值对比 + 确认/取消。

### 4.3 图鉴展示

图鉴编辑页/图鉴视图：精灵行（5470 行附近）已有 `进化→` 标记，扩展为可点击查看"进化链 + 条件"。最小实现：在 suiteMark 或行 tip 中追加 `进化条件文案`（`evoCondText`），例如"进化→炽焰狼王（Lv≥30 · 火亲和≥60）"。**不做进化链树状图**（复杂度高，非必需）。

### 4.4 管理端配置

`openSpeciesForm`（6071 行）表单新增两块：

1. **进化目标**：下拉选择（可选值 = 全部物种中 rarity 高于当前品级的精灵，排除自身；或自由输入 ID）+「+ 添加分支」支持多分支（网状）。保存进 `def.evoTo`（单分支）或 `def.evoToBranches`（多分支）。
2. **进化条件**：条件列表编辑器（每行：类型下拉 lvl/aff/stat + 数值输入；aff 额外选属性；stat 额外选面板键）。保存进 `def.evoCond`（单目标时）或各分支的 `cond`（多分支时）。
3. 保存路径与现有逻辑一致：自定义精灵写 `S.customSpecies[id]`，内置精灵写 `S.speciesEdits[id]`（覆写合并）。**注意**：`S.speciesEdits` 覆写是整对象还是字段合并，读 6071 行保存段确认，保持与现有 drops/essenceName 相同的写入方式。

## 5. 执行流程（玩家侧完整链路）

```
灵兽仓 → 精灵卡片「进化」按钮（条件满足=高亮 / 不满足=置灰+缺条件提示）
  → 点击 → 确认弹窗（目标形态/品级/种族值对比/条件清单）
  → 确认 → evolveSpirit() 校验 canEvolve（二次校验）
  → 结算：speciesId/name 切换 → 新技能解锁进 skillPool → log 追加 → 重渲染
  → toast「进化成功：炎狼 → 炽焰狼王」
```

数据流：`evoCondOk(spirit, cond)` 读 `spirit.lvl`、`spirit.aff`、`spiritStats(spirit)` 面板值 → 全 AND 通过才可进化；`evolveSpirit` 只改 `speciesId`（+name/skillPool/log），面板变化由 `spiritStats` 实时推导。

## 7. 进化链默认条件（配置建议，开发时可微调但需记录）

首版建议 21 条链统一用简单条件，数值随品级递增（后续平衡再调）：

- normal → elite：`[{type:'lvl', v:30}]`（30 级可一阶进化）
- elite → perfect：`[{type:'lvl', v:45}]`（45 级二阶进化）

理由：首版先落地机制闭环；多样化条件（亲和力/面板阈值）作为**能力已支持**但仅用在个别精灵上做演示（例如：火系链一阶额外要求 `{type:'aff', elem:'fire', v:40}`，展示混合条件 UI）。**最终配置数值写入版本记录，测试 agent 以此为准。**

## 8. 验收标准（测试 agent 直接按此断言）

1. **数据完整性**：所有含 evoTo/evoToBranches 的物种目标可解析（目标 ID 存在于 SPECIES）；21 条链无断链（链上每跳目标品级 = 源品级+1 档）；传说 3 只无进化目标。
2. **条件判定**：条件全满足 → `canEvolve` 返回可用分支；任一条件不满足 → 不可进化且 UI 显示缺失条件文案（含当前值 vs 需求值）。
3. **进化结算**：进化后 `speciesId/name/rarity` 切换到目标；`spiritStats` 面板按新种族值变化；`iv/nature/lvl/exp/bonusLv/perks/aff/shiny/source` 全部保留；新物种技能解锁进 skillPool；已装备技能不丢失；log 追加进化记录。
4. **网状进化**：至少构造一组 `evoToBranches` 演示数据（管理端配置或内置），验证：不同条件满足时进化为不同目标（一对多）；多个源物种 evoTo 指向同一目标时可进化为同一目标（多对一）。
5. **管理端配置**：openSpeciesForm 可新增/修改进化目标与条件；保存后（customSpecies/speciesEdits 路径）实际生效（新建自定义精灵可进化验证）。
6. **飞升承接校验**：承接 elite/perfect 灵兽时，用进化链上游形态妖兽 → 成功；用无关形态妖兽 → 拒绝并提示。
7. **UI 入口**：灵兽仓精灵卡片显示进化按钮；条件不满足置灰 + 缺条件提示；确认弹窗含目标形态/品级/种族值对比。
8. **回归**：既有 14 套测试套件全绿（重点 reg_cdp / codex_test / wild_test / stats_test——本次改动涉及 speciesBase 相关展示与 landSpirit 承接路径）。
