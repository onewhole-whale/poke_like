## 1. 版本目标

启用被架空已久的 guard（铁壁）机制为真实减伤技能（免伤值由技能配置传入，不写死），
新建「普」属性（无偏向属性）防御技能作为首个使用者；同时把技能类型（攻击/状态/防御）升级为
功能性顶层字段，并新增技能级冷却字段与列表排序规则。

变更点清单（类型打标）：

| # | 变更点 | 类型 |
|---|--------|------|
| 1 | guard 机制改造：免伤值读 effects.layers，不写死 25% | 战斗机制 |
| 2 | 技能类型 type 升级为「攻击/状态/防御」三分类（功能字段） | 数据模型 |

| 7 | 所有技能 list 展示处统一按 防御 → 状态 → 攻击 排序 | UI |

## 2. 现状核查（v1.13.2 代码事实）

- **guard 现状**：`SKILL_STATUS.guard` 定义存在（4467 行）；`applyMechEffect` case 'guard'
  只写 `b.spBuffs.guard = 1`（布尔标记，4633 行）；读取处写死 `mods.dmgDown += .25`
  （beastTurn 5048 / dgBeastTurn 4023）；回合末 `guard--` 递减（4873 / 3836）。
  **全文件 0 个技能挂 guard**（effects 与 mech 字段均为空）→ 纯死代码。
- **技能 type 字段现状**：仅作展示标签，取值「攻击」34 处、「机制」11 处；功能分类由
  `kind` 承担（direct 模板 / ult / burst / mechanic 回能）。
- **技能编辑器**（M3-P0 已建，6227 行起）：已有 name / elem / kind / track / power /
  hits / energy / cost / accuracy / effects 行 / tags 字段，**无 cooldown**。
- **技能列表分组**：按 kind 分组展示（direct / ult / burst / mechanic，6174 行），
  组内无 type 排序。
- **属性体系**：ELEM = 15 常驻系 + 3 表外（time/star/chaos）；`none` 为无属性占位
  （混乱自伤用，显示「无」，不参与克制）。**不存在「普通」属性，不存在「聚能」**。
- **无冷却机制**：全文件无 cooldown 字段与结算。

## 3. 实现方案

### 3.1 guard 机制改造（免伤值读配置）

- `applyMechEffect` case 'guard'（4633）：`b.spBuffs.guard` 从布尔标记改为存免伤百分比
  数值 `n/100`（ef.layers 传入，如 layers:80 → 0.8）。
- `beastTurn` / `dgBeastTurn` 读取处：`mods.dmgDown += b.spBuffs.guard`（读实际值，
  删除写死的 `.25`）。
- 回合末递减（battleRoundEnd / dgRoundEnd）：`guard--` 改为直接置 0
  （guard 语义 = 本回合生效，回合末消失；存数值后 `--` 会算错，必须改）。
- 兼容：旧存档战斗对象无 guard 或 guard 为 1 → 读 `b.spBuffs.guard||0`，1 表示 100%？
  注意：旧存档里 guard 若是 1（布尔）会被解读为 100% 减伤。战斗对象不持久化
  （每次战斗重建），无兼容问题。确认：S.wild.battle 不落盘 → 安全。

### 3.2 技能类型 type 升级为三分类

- type 字段语义升级：`'攻击'` / `'状态'` / `'防御'`（保留中文值，展示零改动，
  新增排序与约束逻辑按此判断）。
- 存量数据迁移：34 处 `type:'攻击'` 不变；11 处 `type:'机制'` 全部归入
  `'状态'`（用户已确认：均为草系状态技能，无防御型；实现时逐个核对 ID）。
- 引擎约束：`type==='状态' || type==='防御'` 的技能不读 power（power 可缺省或为 0），
  结算路径已天然支持（机制/纯效果技能不结算伤害）。
- 编辑器：type 下拉（攻击/状态/防御）；选状态/防御时 power 输入框禁用。

### 3.3 状态/防御技能威力直接显示「-」

- 展示层（技能卡/技能池列表/所有技能 list）：`power` 为空或 0 且 type 为状态/防御 →
  直接显示「-」（用户定稿：不显示「威力 -」这类带标签形式，就是「-」）。
- 现有逻辑：power 缺失 `sk.power||0` → 0，不结算伤害，行为不变，仅展示层调整。

### 3.4 新增技能级冷却字段 cooldown

- 技能顶层字段 `cooldown`（回合数，缺省 = 无冷却）。
- 战斗对象新增 `b.cds = {}`（技能id → 剩余冷却回合数）。
- `playerTurn` / `dgPlayerTurn` 释放成功后：若技能有 `cooldown`，
  写 `b.cds[sk.id] = sk.cooldown`。
- `skillUsable`（野外）/ 对应秘境可用性判断：`b.cds[sk.id]>0` 时不可用
  （UI 置灰 + 点击提示「冷却中」）。
- 回合末（battleRoundEnd / dgRoundEnd）：遍历 `b.cds` 递减，归零删除。
- 冷却语义：cooldown:1 = 释放当回合结束进入冷却，下一整回合不可用，再下一回合恢复
  （即「不能连续使用」）。
- 秘境侧对称：dgBattleSkill 入口 + dgPlayerTurn + dgRoundEnd 同步实现。

### 3.5 新「普」属性（ELEM.normal）＋ 克制关系落表

- `ELEM.normal = {name:'普', tag:'normal', dot:'dot-normal'}`——新增第 16 个常驻系；
  素材体系/精灵元素下拉/属性筛选自动随 ELEM 扩展（核对各处硬编码 15 系的地方）。
- 克制关系（用户定稿）：**无克制面**（普不克制任何属性）、**不自抵抗**（普不被任何属性抵抗）、
  **被武克制**：`TYPE_CRUSH.fight` 增加 `'normal'`（武攻击普 ×2）；
  **与幽相互抵抗**：`TYPE_RESIST.normal` 含 `'ghost'`（幽攻击普 ×0.5），
  `TYPE_RESIST.ghost` 增加 `'normal'`（普攻击幽 ×0.5）；**定位：均衡**。
- 精灵体系纳入（用户定稿）：无元素偏向的精灵归普系（参考宝可梦普通系——纯动物/
  生物形态、无水火草等元素主题的精灵为普通系）。已盘点现有 66 只精灵：全部有
  明确元素主题（炎狼=火、水狐=水、雷鹰=雷…），**无一只符合「无元素偏向」→
  本次不改动任何现有精灵属性**；普系精灵为未来新增设计预留。
- 类型注释同步：克制网络注释「15 常驻系」→「16 常驻系（+普）」。
- 贯通性/击溃性统计：普加入后若文档有对应统计需同步（仅文档层）。

### 3.6 新技能：【防御】（防御技能初始模板，ID: n_guard）

```
{
  id: 'n_guard', name: '防御', kind: 'ult', type: '防御',
  elem: 'normal', track: 'phys', power: 缺省（显示 -）, hits: 1,
  energy: 1, cost: 1, cooldown: 1, accuracy: 100,
  desc: '凝神定势，本回合受到伤害减少 80%，随后进入 1 回合冷却。',
  effects: [{ target:'self', type:'guard', layers: 80 }]
}
```

- 名称定稿：**「防御」**（作为防御技能的初始模板技能，ID 保留 n_guard）。
- 属性：`elem:'normal'`（普）。
- 能耗/容量：用户定稿 **能耗 1 / 容量 1**（总代价 1）。
- 加入 GLOBAL_SKILL_POOL / 白名单 / 图鉴标签体系（若有校验白名单需同步）。

### 3.7 技能表排序：防御 → 状态 → 攻击（所有技能 list）

- **范围**（用户定稿）：出现技能 list 的地方全部调整——管理员技能池、
  玩家技能配置页等所有技能列表展示处。
- 排序：主键 = type 大类序（防御 0 < 状态 1 < 攻击 2），组内维持现有 kind 分组序
  （direct / ult / burst / mechanic）。
- 实现位置：skGroups 分组逻辑（6174）＋玩家配置页技能列表排序处统一改造。

## 4. 执行流程（运行逻辑链）

- **防御技能释放**：选「防御」→ skillUsable 检查（能耗 1 ✓ 冷却 0 ✓）→
  playerTurn → preMech 命中（guard 在 preMech 列表）→ applyMechEffect('guard')
  写 spBuffs.guard=0.8 → 写 b.cds['n_guard']=1 → 本回合敌方攻击时 beastTurn 读
  guard → mods.dmgDown += 0.8 → 伤害 ×0.2 → 回合末 guard 置 0、cds 递减 → 下一回合
  「防御」置灰（冷却中）→ 再下一回合恢复可用。
- **普属性克制链**：武系攻击普系 ×2；幽/普互攻 ×0.5；其余属性攻普 ×1。
- **冷却机制通用链**：释放 cooldown 技能 → 写 b.cds → 后续回合 skillUsable 拦截 →
  回合末递减 → 归零恢复。

## 5. 验收标准（测试 agent 输入）

1. **guard 读配置**：配 guard layers:80 的技能，敌方攻击我方时受到伤害 = 原伤害 ×0.2
   （误差 ±1，向下取整）；layers:50 → ×0.5。不再固定 25%。
2. **防御技能**：使用「防御」后，本回合敌方伤害 ×0.2；本回合结束冷却开始；
   下一回合该技能不可用（UI 置灰 + 不可触发）；再下一回合恢复可用。
3. **普属性**：ELEM 新增「普」且编辑器/筛选可选；**无克制面**（普克任何属性 ×1）、
   **不自抵抗**（任何属性攻普除武/幽外 ×1）；武攻击普 ×2；幽攻普 ×0.5、普攻幽 ×0.5。
4. **type 三分类**：所有技能 list（管理员技能池/玩家配置页）按 防御 → 状态 → 攻击
   排序；状态/防御技能威力直接显示「-」；存量 11 个「机制」标签技能全部归入状态
   且行为无回归。
5. **冷却通用性**：任意技能配 cooldown:N，释放后 N 回合内不可用，回合末递减正确；
   秘境战斗（dg 侧）同样生效。
6. **无回归**：既有 34 攻击 + 11 状态技能行为不变；reg_cdp / mech_test /
   mech_accept_test 全通过；新技能可被编辑器编辑并保存。

## 6. 验证方式
