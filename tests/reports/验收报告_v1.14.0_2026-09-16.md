## 3. 差异清单（给开发 agent 的核心反馈）

### #1【一般】11 个「机制」标签技能未按设计迁移为「状态」（开发报告 §3.2/§7.5 声称已落地，代码未改）

- **功能点**：type 三分类归并（验收标准 §5.4）
- **设计预期**：§3.2/§7.5「存量 11 处 type:'机制' 全部归入 '状态'（均为草系状态技能）」
- **实现现象**：GRASS_POOL 中 g_leechseed / g_stunspore / g_sleeppowder / g_spores / g_cottonspore / g_synthesis / g_aromatherapy / g_cottonguard / g_grassyterrain / g_strengthdrain / g_spicyextract 共 11 个技能 `"type": "机制"` 原样保留（1426 行起，JSON 双引号格式），运行时统计：攻击 491 / 状态 1（仅回能）/ 防御 1 / **机制残留 11**。
- **连带影响**：① `typeRank`（6222 行）把 type='机制' 归为 2（攻击类）→ 这 11 个状态技能在列表里排到攻击技能之后，与设计「防御→状态→攻击」不符；② 技能卡 kind 标签仍显示「机制」；③ 编辑器打开这些技能时 type 下拉因无「机制」选项默认指向「攻击」（见观察点 #4）。
- **严重程度**：一般（排序与展示层与设计不一致；引擎结算无影响——power=0 不结算伤害，行为无回归）
- **修复建议**：将 GRASS_POOL 中 11 个技能 `"type": "机制"` 改为 `"type": "状态"`（逐 ID 核对，均为草系状态技能，无防御型）；顺带把 kind 显示映射中的「机制」字样按新语义核对。

### #2【一般】技能冷却实际生效 N−1 回合：cooldown:1 完全无效，cooldown:N 只有 N−1 回合不可用（野外/秘境同病）

- **功能点**：冷却通用性（验收标准 §5.2/§5.5）
- **设计预期**：§3.4「cooldown:1 = 释放当回合结束进入冷却，**下一整回合不可用**，再下一回合恢复（即不能连续使用）」；§5.5「任意技能配 cooldown:N，释放后 **N 回合内不可用**」
- **实现现象**：`playerTurn` 释放时写 `b.cds[sk.id]=sk.cooldown`（3965 行），而**同一回合末 `battleRoundEnd` 立即递减一次**（4888 行 `b.cds[k]--`，秘境对称 dgRoundEnd 3845 行）→ cooldown:1 写入 1、回合末减到 0 删除，**下一回合即恢复可用**；cooldown:2 写入 2、回合末减到 1 → 只有 1 个完整回合不可用，第 2 回合就恢复。实测（guard_accept_test C/D/E 段）：n_guard 释放后 R2 仍可用（`skillUsable=true`）；cd_test(cooldown:2) 释放后仅 R2 不可用、R3 恢复（设计应 R2、R3 均不可用）；秘境 dg 侧同样（dgBattleSkill 后 `dgSkillUsable=true`）。
- **影响**：n_guard 的「1 回合冷却」形同虚设 → 可连续回合释放防御（实测 R2 点击防御仍生效减伤）；任意 cooldown:N 技能的不可用窗口比设计少 1 回合；UI 置灰路径（`skill-btn off`）因 `skillUsable` 恒 true 而不会触发。
- **严重程度**：一般（冷却是新机制，语义与设计不符；对 n_guard 的"不能连续使用"承诺不成立）
- **修复建议**（择一）：① 写入时 `b.cds[sk.id] = sk.cooldown + 1`（把释放当回合计入），回合末递减逻辑不变——语义变为：cooldown:1 → R2 不可用、R3 恢复；cooldown:2 → R2/R3 不可用、R4 恢复（与设计逐条吻合）；② 或回合末递减跳过「释放当回合」（加标记）。**双引擎同步修改**（野外 battleRoundEnd 4888 / 秘境 dgRoundEnd 3845 同构）。

### #3【警告】技能编辑器打开「机制」技能时 type 下拉默认指向「攻击」（保存会把状态技能改成攻击）

- **功能点**：编辑器 type 三分类（§3.2）
- **实现现象**：`typeSel` 默认值 = `base.type || (power>0?'攻击':'状态')`；11 个机制技能 `base.type='机制'` 不在下拉选项（攻击/状态/防御）中 → 无选中项，浏览器默认选中第一个选项「攻击」。若管理员打开一个机制技能直接点保存（未显式选 type），`typeSel.value='攻击'` 会写入 → 状态技能被误改。
- **严重程度**：警告（数据误改风险，需手动保存才触发）
- **修复建议**：下拉选项加入「机制」兼容项（value='机制'，提示归入状态），或在打开时把 type='机制' 映射为「状态」选中。

### 已确认无问题的观察点

- **guard 减伤逐段取整**：实测释放防御后伤害比例 0.23（52→12），逐段 floor 取整导致略高于理论 0.2，属公式既有取整行为，非差异。
- **技能编辑器 type 语义**：新增技能默认「攻击」；状态/防御技能 power 填 0 列表显示「-」——符合 §3.3。

## 6. 最终结论

**【存在不一致，待修复】**

- 功能通过：guard 机制复活（读配置减伤数值正确）、防御技能 n_guard（定义/释放/本回合减伤 80%）、普属性完整克制链、威力显示「-」、排序框架、编辑器 type/cooldown 字段、22 套回归全绿（0 回归破坏）。
- 2 条【一般】差异：
  1. **11 个机制技能未迁移为「状态」**（开发报告 §3.2/§7.5 声称已落地，GRASS_POOL 原样保留 type:'机制'）→ 排序与展示与设计不符。
  2. **冷却少算 1 回合**（写入与回合末递减同回合抵消；cooldown:1 完全无效、cooldown:N 只生效 N−1 回合；野外/秘境同病）→ n_guard 可连续释放，防御技能"不能连续使用"承诺不成立。
- 1 条【警告】：编辑器打开机制技能 type 默认「攻击」，直接保存会把状态技能误改。

**建议开发侧处理顺序**：#2 冷却（影响新机制核心语义，一行修复）→ #1 机制迁移（11 处 type 字段）→ 观察点 #3。
