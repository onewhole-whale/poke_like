## 3. 差异清单（给开发 agent 的核心反馈）

### #1【一般】refineFate 未持久化：刷新后缘分计数丢失，120 保底无法跨刷新累计

- **功能点**：炼化 120 次硬保底（需求 §2.8/§4.2、开发报告 §3.2/§5.2）
- **设计预期**：`S.refineFate` 随 saveDraft 持久化、刷新保留（旧档缺省 {} 兼容）
- **实现现象**：`saveDraft`（2876 行）只写 matEdits/customMats/speciesEdits/customSpecies/tagLib/essences/refineRules/skillEdits/dexSeen/dexClaimed——**不含 refineFate**；`init`（2164 行）也不读。实测 saveDraft 后 localStorage 草稿 `refineFate=undefined`。fate 计数仅存内存，刷新即清零，保底进度无法跨会话累计。
- **影响**：120 次保底"30 天必出"承诺依赖刷新不重置；当前刷新一次保底计数归零。
- **严重程度**：一般（保底进度丢失，核心承诺受影响）
- **修复建议**：saveDraft 增加 `refineFate:S.refineFate`，init 增加 `if(d.refineFate) S.refineFate={...d.refineFate}`（与 v1.13 dexSeen/dexClaimed 同款修法）。

### #2【一般】TOOL_TREE 48 种工具数据结构未建（含 S.tools→toolInv 迁移缺失）

- **功能点**：采集工具框架（开发报告 §3.5/§5.6、需求 §2.10）
- **设计预期**：§3.5「TOOL_TREE：8 细分（木头/花草叶/水生/果实/金属/石料/气体）× 6 品质 = 48 种工具数据结构 {id,name,subtype,quality,capacity,durability,yield}」；S.tools 重构为 S.toolInv（旧档数字迁移）
- **实现现象**：全文件无 TOOL_TREE / yield / durability / subtype；`S.toolInv:{}`（1773 行）仅声明空对象，无任何读写；S.tools 仍为矿镐计数（5588/6037/6156/6174 行使用中），**旧档 tools 数字→toolInv 迁移逻辑不存在**；collectTile 硬编码 `hasTool=false`（5763 行）。
- **影响**：工具系统纯框架缺失；品质占用 1/3/5/7/9/11、出货池≤工具品质、顶替规则（需求 §4.5/§4.6 可断言项）无载体；本期无工具路径可跑，但验收标准 §5.6「48 种可定义」未达成。
- **严重程度**：一般（本期"默认空手"可运行；数据结构承诺未落地）
- **修复建议**：按 §3.5 建 TOOL_TREE（8 细分 × 6 品质 × yield/durability），collectTile 出货池改从工具品质取；S.tools 旧档迁移（typeof S.tools==='number' → toolInv['pick_normal']=(S.tools||0)）。

### #3【一般】BATTLE_BUFFS 战斗内效果未实现：battleBuffs 仅存储，无回合末结算

- **功能点**：战斗全程 buff（开发报告 §3.7/§5.8、需求 §2.9.7）
- **设计预期**：§3.7「b.battleBuffs=[...]；回合末 tickBattleBuffs 结算（回血/回能/减伤等）；本期实现 3 个核心 buff：b-regen（回血 12%）、b-energy-5（回能+5）、b-harden（减伤 8%）」；§5.8「效果可验证」
- **实现现象**：`battleBuffs` 全文件仅 2 处引用——startBattle 参数接收（5002 行）与 battle 对象存储（5014 行）。**无 tickBattleBuffs、无任何回合末结算/效果应用点**；b-regen/b-energy-5/b-harden 只在 BATTLE_BUFFS 表里定义数据，战斗内无效果。genSandbox 虽实例化 buffs 传入 startBattle，但战斗全程无感。
- **影响**：buff 系统目前是"只建表不生效"；验收断言「效果可验证」失败。
- **严重程度**：一般（机制框架在，效果缺失）
- **修复建议**：实现 tickBattleBuffs（battleRoundEnd/dgRoundEnd 调用）：b-regen 按 params.pct 回血、b-energy-5 每回合末 +5 能量（≤上限）、b-harden 并入 mods.dmgDown（calcDamage 路径），按 buff.side 作用对象；双引擎同步。

### #4【一般】事件密度不符：实测战斗+奇遇 72.6%（全事件 100%），需求「~50%（±5%）」

- **功能点**：沙盒事件密度（需求 §2.9.1/§4.3、开发报告 §5.3）
- **设计预期**：§4.3「事件密度 ~50%（±5%）」（45%~55%）
- **实现现象**：MAP_CONFIGS.7mid.eventWeights = fight:.55 + wonder:.2 + gather:.25（4531 行）→ genSandbox 每格必落入三类之一：实测 100 次生成 ×49 格：战斗 53.5%、奇遇 19.1%、采集 25.3%——**战斗+奇遇合计 72.6%、含采集格全事件 100%**，两种口径均远超 50%±5%。
- **影响**：每把战斗数 ≈ 26 格 ×7×7 期望远高于设计节奏（7×7≈12 战），炼化节奏/素材产耗比（需求 §2.2）随之上浮。
- **严重程度**：一般（数值节奏偏差；若按"战斗+奇遇=事件"口径为 72.6%）
- **修复建议**：将 eventWeights 调整为战斗+奇遇合计 ≈ 0.5（如 fight:.35 + wonder:.15 + 其余空格无事件/仅资源格），或明确「事件密度」口径后按口径调权。

### #5【一般】空手采集「仅普通」未达标：出货池含精良素材

- **功能点**：空手采集规则（需求 §2.10.2/§4.5「无工具 50% 出货率仅普通」）
- **实现现象**：collectTile 出货池硬编码 `c.ore>0 ? ['ironore','terra','chips'] : ['chips','herb','spiritherb']`——其中 **terra（964 行 quality:'fine'）、spiritherb（959 行 quality:'fine'）为精良品质**，空手可采出。实测 100 次采样出货 54 次中 18 次为精良素材（非普通）。
- **影响**：空手采集的"体力效率惩罚"设计（仅普通品质）失效，产出品质高于设计。
- **严重程度**：一般
- **修复建议**：空手路径从普通品质池取（matPool 过滤 quality==='normal'，或空手直接 roll 一个普通品质素材）。

### #6【一般】moveTo 无边界校验：越界调用抛 TypeError

- **功能点**：沙盒移动边界（需求 §2.9.3/§4.4「边界不可越」）
- **实现现象**：moveTo（5727 行）无边界检查，直接 `w.grid.cells[y][x]`——测试 `moveTo(-1,0)` 抛 `Cannot read properties of undefined`。UI 层移动按钮只生成相邻合法格（5694 行 isAdj 判定），正常路径不触发；函数层无防护。
- **影响**：函数级健壮性缺口（脚本/未来 UI 若直接调 moveTo 越界即崩）；验收断言「边界移动正确」在函数层不成立。
- **严重程度**：一般
- **修复建议**：moveTo 开头校验 `if(x<0||y<0||x>=w.grid.size||y>=w.grid.size) return;`

### 观察点（不阻塞，供开发侧记录）

- **O1【观察】** rollBattleBuffs normal 档：需求 §2.9.7「普通 = 无 buff 或双方同时获得同一 buff」；实现为 neutral→both、非 neutral → `Math.random()<.5 ? player : beast` 随机单方（4632 行），与"双方同"不符。本版地图 difficulty 硬编码 'normal'，该分支实际生效。

- **O3【观察】** EVENTS 表未按名建立：实现仅 `FIGHT_EVENT_BASE`（战斗事件基类）；wonder 沿用 WONDERS、无独立基类；**adventure（冒险事件）类缺失**（开发报告 §3.8「EVENTS 3 类」）。本版"内容下版填充"，kind:'gather' 承担资源格采集，非冒险事件。
- **O4【观察】** BATTLE_BUFFS id 与需求 §2.9.7 补充表不完全一致：b-regen-20/b-shield-8 未建，实现补入 b-energy-3（回能潮+3）与 b-regen（再生12%，即用户案例3）；需求标注"固定数值，可调"，不判 FAIL。
- **O5【观察】** 采集品质占用 1/3/5/7/9/11 与工具品质池/顶替规则未落地：本期无工具路径固定占用 1，完整算法依赖 TOOL_TREE（差异 #2），属开发报告 §7 版本边界（工具制作下版）。
