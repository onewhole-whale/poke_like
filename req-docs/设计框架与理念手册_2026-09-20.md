# 炼妖壶 · 灵兽养成 —— 设计框架与理念手册

> 本文档是给新接手的产品经理 / 开发者的"设计圣经"。
> 读完这份文档，你应该能理解这个游戏为什么这么做、各种设计决策背后的思考，以及后续设计时应该遵循什么原则。
> 不包含具体的数值表和配置数据——那些在需求文档和代码里。

---

## 一、核心设计理念

### 1.1 我们在做什么

**题材**：精灵收集 + 异色收集。

**核心矛盾**：传统捉宠游戏（宝可梦/赛尔号）鼓励大量抓取同类刷资质，导致玩家和精灵之间没有情感连接——抓一百只火系精灵，哪只是"我的"？

**我们的解法**：
- 灵兽（培养主线）**只能通过炼化获得**——投入素材炼妖，绝大多数时候出培养材料，小概率出灵兽
- 灵兽天生资质顶尖、性格自选、个体值自选
- 妖兽（野外捕捉）资质随机，是兼容玩法，可通过"飞升"继承情感连接

### 1.2 情感连接三来源

用户（产品总监）的原话归纳：
1. **来历**——剧情/任务/赛季送的精灵（本作：炼化来源、奇遇、加冕）
2. **经历**——好用、长期使用的工具宠（本作：陪伴战斗、副本冒险）
3. **不可替代性**——同种唯一、形象区分（本作：普通灵兽同种唯一、异色独立、加冕改名）

### 1.3 反对什么

- **反对批量刷取**——不是抓一百只刷资质，而是一只灵兽陪你走到底
- **反对数值膨胀**——技能设计有严格的代价标尺，不搞超模技能
- **反对技能池限制**——因为我们所有精灵都能学任意技能，所以更要控制终局技能数量

## 二、技能设计理念

### 2.1 代价公式（核心标尺）

**代价 = 能耗 + (容量 - 1)**

- 每个技能默认占 1 点容量
- 能耗 = 代价 - (容量 - 1)
- 1 点容量是"基础成本"，攻击技能里赋予效果状态 1 层算 1 点代价，状态技能里 2 层算 1 点

**威力标尺**：
- 40 威力 = 无代价（0 能耗）
- 每 +1 代价，威力 +20
- 120 威力 = 无副作用上限（5 代价）

**技能分层**：
| 层级 | 代价 | 定位 |
|---|---|---|
| 过渡 | 0~1 | 前期用，后期淘汰 |
| 亚终局 | 2~3 | 中期主力，亚终局 |
| 标准终局 | 4~5 | 终局主力 |
| 爆发 | 6+ | 大招 |

### 2.2 为什么控制终局技能数量

**宝可梦的问题**：
- 每个属性真正好用的终局技能就 3~4 个（比如火系：喷射火焰/大字爆炎/热风/闪焰冲锋）
- 其他都是下位替代或过渡技能
- 这是故意的——控制强度，避免超模技能流向强精灵

**我们的情况**：
- 所有精灵都能学任意技能（没有技能池限制）
- 如果设计一堆超模终局技能，谁拿到谁就无敌
- 所以更要控制——每个属性终局技能就 3~4 个，其他用亚终局/过渡技能填充

**怎么引导玩家用过渡技能**：
- 终局技能卡产出——放在高难副本/周本里
- 大部分玩家很长时间只能用亚终局技能
- 前面有终局技能吊着，有动力刷

### 2.3 对同类游戏的评价

**宝可梦**：
- 技能设计感差——很多技能彼此上下位，终局技能有限
- 精灵种族值/特性/技能池综合成整体，用精准刀法适配环境
- 中期游玩时间长，获取更强技能本身就是乐趣
- 打击面本身就是特点，技能不需要太花哨

**洛克王国世界**：
- 技能设计感更强——每个属性特色突出
- 但平滑性没那么好（才出 1 年不到，正常）
- 抄它的机制设计，但不要照抄数值

**我们的选择**：
- 学洛手的属性特色设计（每个属性有自己的机制特点）
- 学宝可梦的技能分层控制（终局少、亚终局填充）
- 因为是 PVE，超模也不是太危险，但还是要控制

## 三、属性设计倾向

### 3.1 15 属性定位

| 属性 | 定位 | 核心机制 |
|---|---|---|
| 火 | 暴力输出 | 灼烧状态 + 大威力攻击 |
| 水 | 净化+能耗操控 | 清除负面 + 能耗下降/上升 |
| 草 | 吸血+状态 | 寄生种子 + 吸血技能 + 大数值（抗性差所以可以超模） |
| 风 | 连击流 | 多段攻击 + 提升连击数 |
| 土 | 防御联动 | 物防联动技能 + 防御技能 |
| 雷 | 麻痹+速度差 | 麻痹状态 + 利用速度差增伤 |
| 冰 | 冻结状态 | 各种冻结附加（冰系抗性差所以超模效果合理） |
| 暗 | 吸血+血量联动 | 吸血状态 + 血量越低越强 |
| 幽 | 偷能量 | 各种偷能量 + 状态技能 |
| 光 | 自由属性 | 基于携带技能属性触发不同效果（情报对策卡） |
| 虫 | 献祭玩法 | 利用其他虫系精灵发挥效果（现在只能带一只，以后会改） |
| 武 | 后发制人 | 条件增伤/免伤（预判型） |
| 灵 | 自我增幅 | 各种自身状态技能 |
| 普 | 标准模板 | 所有技能的本真状态（其他属性的同类技能对照） |
| 毒 | 中毒永续 | 高比例中毒 + 耗死对手 |
| 钢 | 特防联动 | 围绕特防 + 防御 |

### 3.2 状态分类

**效果状态**（永续或回合制，影响战斗机制）：
- 中毒、灼烧、冻结、麻痹、睡眠、寄生种子等

**属性状态**（层数制，影响面板数值）：
- 攻击提升、防御提升、速度提升、吸血、连击数增加、能耗下降等
- 每层 ±10%（速度每层 ±10 点）

## 四、系统设计原则

### 4.1 数据层设计

**表结构三层继承**：
- **层0（基类表）**：定义最基础的特征，比如地形块、事件块、技能
- **层1（派生表）**：地图/精灵/具体实例，在基类基础上做细节填充
- **层2（实例）**：进入游戏时才完全定义

**为什么这么做**：
- 减少重复配置——基类定义一次，派生时只改差异
- 方便后续新增——加新地图只需要派生，不用重新定义所有地块

**编码规范**：
- 精灵 ID：`JL_<属性>_<品质>_<4位数字>`
- 素材 ID：`SC_<属性>_<品质>_<6位数字>`
- 道具 ID：`DJ_<属性>_<6位数字>`
- 纯英文+数字，不用中文（避免名称变动导致引用失效）

### 4.2 数值设计原则

**等级和面板**：
- 宝可梦式 lvl³ 升级曲线
- 种族值分档：普通 280-390 / 精英 400-490 / 完美 500-590 / 传说 620-640
- 个体值：1-20 点，最多 3 项
- 性格：±10% 两项面板

**经验获取**：
- 战斗经验 = max(5, 敌方等级 × 基础经验值) × 模板系数
- 基础经验值：普通 10 / 精英 20 / 完美 30 / 传说 40
- 模板系数：普通 ×1.0 / 精英 ×2.0 / 首领 ×3.0
- 副本经验 ×5

### 4.3 UI 设计原则

**平台**：PC 端横屏（后续可能转移动端竖屏）

**战斗 UI 布局**（参考太吾绘卷）：
- 左右展示板从顶到底：立绘+名字+状态栏+队列栏
- 顶部中间：血条+回合数+能量
- 中间：战斗场地
- 底部：功能栏+详情栏（技能/日志/背包/逃跑切换）

**设计原则**：
- 信息密度高但不拥挤
- 对称布局（左右展示板镜像）
- 先用占位方案，后续可整体替换

## 五、核心玩法系统：冒险沙盒与副本构建

> 这两个是游戏的核心玩法循环——野外冒险（沙盒探索）和副本构建（素材投入刷收获）。

### 5.1 冒险沙盒（野外探索）

**玩法参考**：太吾绘卷早期版本的走格子 + 杀戮尖塔的肉鸽事件。

**核心循环**：
1. 选择一张冒险地图（微风平原/静水沼泽/冒烟火山等）
2. 进入后生成随机沙盒地图（7×7 或 5×5 或 10×10）
3. 玩家在格子上移动，未去过的格子触发事件
4. 到达出口格子即可离开

**两层地图结构**：
- **第一层：地形图**——满格覆盖，每个格子是什么地形（草原/湖泊/山地等）
- **第二层：事件图**——不是每个格子都有事件，随机分布战斗/冒险/奇遇事件

#### 地块表三层继承

| 层级 | 内容 | 例子 |
|---|---|---|
| 层0（地形基类表） | 地形的基础特征：类型/植被/尺寸/属性偏向 | 草原=平原类/草原植被/草+普通属性 |
| 层1（派生地形表） | 地图级配置：本地图有哪些地块、各地块素材产出/敌人池/资源量范围 | 微风平原的草原=草素材+草系敌人 |
| 层2（实例） | 进入沙盒时完全定义：具体哪个格子是什么地形、哪个格子有什么事件 | 这局游戏(3,2)是草原+战斗事件 |

**为什么这么设计**：
- 层0定义"草原是什么"——所有地图通用
- 层1定义"微风平原里的草原出什么素材、遇什么敌人"——地图个性化
- 层2是这局游戏的具体实例——随机性在这里体现

#### 沙盒地图生成流程

**步骤1：落锚点**
- 按优先级依次落锚：平原 > 水域 > 山地 > 高原
- 每个锚点是一个大类（不是具体地块），比如"山地锚"
- 山地锚下面挂多个具体地块（高山/丘陵/山谷等），扩张时随机选

**步骤2：向外扩张**
- 所有锚点同时向外扩散
- 冲突时按优先级判定归属（平原 > 水域 > 山地 > 高原）

**步骤3：河流锚（最后落）**
- 在所有地形生成完后，选一个边缘/高山/高原地块作为河流起点
- 按长度参数线性延伸，遇水域就结束

**步骤4：变体地块（后生成）**
- 找随机一个基底地块落锚（比如沼泽）
- 按配置的尺寸区间侵蚀式扩张
- 只能侵蚀同类地块（毒瘴沼泽只能侵蚀沼泽类）
- 遇非同类就停止

**步骤5：事件生成**
- 在已有的地形图上随机铺事件
- 战斗事件/冒险事件/奇遇事件按地图配置的数量生成

#### 事件系统三层结构

| 层级 | 内容 |
|---|---|
| 层0（事件基类） | 事件类型：战斗/冒险/奇遇 + 基础效果 |
| 层1（派生事件表） | 地图级配置：本地图有哪些事件、各类型数量、难度占比、敌人池 |
| 层2（实例） | 具体触发哪个事件、敌人是谁、buff是什么 |

**战斗事件细分**：
- 普通模板：正常敌人
- 精英模板：血×3 攻防×1.5
- 首领模板：血×4 攻防×2
- 难度：简单/普通/困难（决定buff对哪方生效）

**冒险事件**：文字冒险分支链（类似群星事件系统）
- 一个起点，多个选择分支，不同结局不同收获
- 可重复触发

**奇遇事件**：一次性传奇事件
- 一个地图就3个左右，触发过就没了
- 一次性，完成就消失

#### 冒险中的行动

| 行动 | 消耗 | 说明 |
|---|---|---|
| 移动 | 1 体力 | 上下左右走一格 |
| 采集 | 1 体力 | 在已探索的格子上采集素材 |
| 驻扎 | 1 体力 | 休息回血回能（按地块属性偏向匹配） |
| 触发事件 | 0 体力 | 走到新格子自动触发 |

**体力系统**：上限 120，6 分钟回 1 点。进入地图不耗体力，移动/采集/驻扎各耗 1 点。

### 5.2 副本构建（秘境）

**玩法参考**：杀戮尖塔式的肉鸽连战 + 素材投入构建敌人。

**核心循环**：
1. 投入素材（决定存在分/技能池/专长池）
2. 自动生成敌人（妖兽素材→妖兽，植物素材→元素灵，矿石素材→魔像）
3. 多轮连战（每次单挑，每5场回满+抽buff）
4. 通关结算（按存在分抽技能/专长 + 经验×5）

**存在分机制**：
- 每属性独立 1000 分容量
- 投入素材的"可提取信息"转化为存在分
- 1 存在分 = 1/1000 的抽取概率
- 存在分决定技能池/专长池的大小和概率

**敌人生成规则**：
- 妖兽素材：每 5 个单位出 1 只对应妖兽
- 植物素材：出元素灵（完美品质，图鉴可查）
- 矿石素材：出魔像（同元素灵）
- 敌人等级 = 出战灵兽等级

**连战机制**：
- 每次单挑一只
- 每 5 场回满状态 + 抽 1 个常驻 buff
- buff 可叠加可重复（面板+10%/回能+1/能量上限+5等）
- 全灭通关或力竭败退

**挂机修炼**：
- 复刻副本记录——选一次历史副本，投入对应素材
- 本质是快速结算副本，经验量 = 那次副本的总经验
- 15 分钟一次，3 个挂机槽位
- 只有灵兽可挂机，挂机中不能进野外/副本

## 七、产品总监的偏好和红线

### 7.1 命名红线

**禁用字**：圣、神、魔

除非产品总监主动要用，否则自动生成精灵名/素材名时不能用这三个字。

### 7.2 文档规范

- 需求文档只落本地一份，不创建飞书在线副本
- 需求文档结构：背景→详情→参考案例→验收标准→待拍板
- 验收标准必须可观测、可断言

### 7.3 设计偏好

- **不拍板**：产品经理只给选项和推荐，方向决策权在产品总监
- **不脑补**：未定的设计标注【待拍板】，不自行补全
- **哲学一致**：所有设计必须服务核心设计理念（情感连接/反对批量刷取）
- **最小介入**：只讨论被点名范围，已落地/已否决的不重复提

## 九、给新接手产品经理的建议

1. **先读 DEVELOPMENT_PLAN.md**——这是活文档，记录了所有已落地内容和待做内容
2. **再读本文档**——理解设计理念和背后的思考
3. **遇到不确定的设计决策**——标注【待拍板】，不要自行脑补
4. **有不同意见可以说**——但要讲清楚取舍和代价，不是和稀泥
5. **参考前辈游戏**——宝可梦/洛克王国/赛尔号/明日方舟/太吾绘卷都是我们的参考对象
