# M3-1-5b 补丁 · 技能字段填写规则（cost / energy）· 需求文档

- **版本**：v1.0（2026-09-19）
- **前置**：M3-1-5b（技能填充，需求 v1.1 已交开发，开发进行中）
- **范围**：修正 40 门样板技能的字段填写口径——`cost`（容量）与 `energy`（能耗）的取值规则；**v1.1 其余内容一律不变**
- **性质**：补丁需求（开发已开工，不覆盖 v1.1 正文，按本补丁追加执行）

## 1. 需求背景与目标

v1.1 §2.1 中「技能 `energy`（战斗能量消耗）默认 = `cost`」表述与产品总监设计口径不符，会导致开发把"代价"误填为能耗、且容量取值无据（若按效果类型加容量则全体技能亏模）。

**真实设计口径（产品总监原稿，拍板确认）**：技能「代价」是**总强度预算**，由能耗与容量共同构成：

```
代价 = energy + (cost − 1)
```

默认每技能 **1 点容量**（cost=1），因此：

```
energy = 代价 − 1
```

**目标**：开发按本补丁填写 40 门技能字段，保证总代价与设计表一致（不亏模、不超模），且不影响开发中进度。

## 2. 需求详情

### 2.1 字段语义（确认）

| 字段 | 语义 | 系统约束 |
|---|---|---|
| `cost` | 技能容量占用（装配层，受亲和力修正） | 回能（机制技能）为 0，普通绝技统一 1 |
| `energy` | 战斗能量消耗 | 能量条上限 20；使用判定 `b.energy >= energy`；爆发清空能量 |

### 2.2 填写规则

- **40 门样板技能（全为绝技 kind:'ult'）**：`cost = 1`，`energy = 代价 − 1`；
- **回能（SKILLS.universal regen，机制技能）**：`cost = 0`，`energy = 0`（不占容量、默认携带，v1.1 已定，不变）；
- **`costdown`（减费）效果作用于 `energy`（战斗能耗）**，与容量无关（水属性"减少费用消耗"特质同理）；
- 本版无 burst 技能，不涉及爆发条件字段。

### 2.4 与存量实现的关系

- 草系等存量池技能容量 1~5 为历史实现，**本补丁不改存量**；新技能统一容量 1；
- 技能列表排序沿用「组内按代价（能耗+容量−1）从低到高」逻辑，本补丁填写后 40 门技能按 1→7 代价自然排序正确。

## 4. 验收标准（可观测 · 可断言）

1. **字段值**：40 门技能 `cost` 全部 = 1（回能 = 0）；
2. **能耗**：每门 `energy` = 表内「代价 − 1」的值，逐一对照 §2.3 表，任何一门不符即失败；
3. **总代价一致**：按 `energy + (cost − 1)` 计算，每门 = 设计代价（2~7），无亏模/超模；
4. **战斗可用**：能量判定 `b.energy >= energy` 正常；镜面防御（energy=0）无需攒能可直接释放；
5. **排序**：技能列表按代价（能耗+容量−1）从低到高正确排列（镜面防御 1 代价排最前、暴风雪 7 代价排最后）；
6. **v1.1 其余内容不受影响**：机制升级、草系迁移等按 v1.1 原样执行。
