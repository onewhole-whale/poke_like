# 需求文档 M3-2 补丁 a · P0 流程修复

> 版本：v1.1 | 日期：2026-09-21 | 性质：M3-2 补丁 a（P0 级流程修复）
> 更新：2026-09-21 第 5 节待拍板项已由产品总监全部拍板（需求评审产出）
> 前置：M3-2 主需求 + 两个补丁（已完成 v1.20.0~v1.20.4）；本文档承接产品核查发现的 4 个 P0 问题。

---

## 一、需求背景与目标

M3-2 战斗演出主体验已落地（布局/血条/能量/状态图标/结果弹框），但产品核查发现 4 个 **P0 级问题**，共同特征是：**已上线的功能处于"看似可用、实际不可用"或"闭环破损"状态**，会直接卡断核心玩法循环。

| # | 问题 | 现状 | 违反的设计意图 |
|---|---|---|---|
| P0-1 | 妖兽出战战斗必败 | 出战妖兽技能列表为空，战斗中只有「回能」，无任何输出，敌方血量不减，玩家被磨死 | 设计手册 1.1：妖兽是"兼容玩法"，UI 明示"野外冒险可出战"；飞升前置需要妖兽经历战斗（情感连接·经历） |
| P0-2 | 野外战斗无视技能编辑器 | 野外引擎查原技能池 SKILLS，副本引擎查 skillById（含编辑覆盖）→ 编辑/新增技能野外点击无反应或用旧数值 | v1.19.x 定稿"技能编辑即时生效并持久化"；双引擎行为分裂 |
| P0-3 | 野外遭遇妖兽策略是死代码 | 遭遇节点 UI（安抚/战斗/离开/突袭/被突袭应战）无调用点，遇敌直接进战斗 | 设计手册 5.1：冒险沙盒"遭遇妖兽可战可抚"；v1.13 前已落地、M3-1 网格化时被整段废弃未接线 |
| P0-4 | 战斗捕捉妖兽不点亮图鉴 | 结果弹框捕捉分支直接 push 入库，未调 markDexSeen | M2-C 图鉴口径："妖兽野外捕获算点亮"，收集闭环破损 |

**目标**：4 项修复，行为对齐设计意图，野外/副本双引擎规则一致，零数值膨胀（不新增技能标尺外的数值）。

## 二、需求详情

### P0-1 妖兽出战：补直接攻击技能，战斗可正常获胜

- **现状**：`wildSpirit()` 妖兽分支返回 `skills:[]`，`startBattle`/`renderBattle` 均无妖兽技能兜底 → 战斗必败。
- **方案 A（推荐）**：妖兽出战时的战斗技能 = `directUnlocked(妖兽属性, 妖兽等级)` 的直接攻击列表（**与敌方妖兽 AI 同规则**，代码同源），另加固定「回能」卡。能量初始 5 / 上限 10 沿用现有战斗对象。
- **方案 B**：禁止妖兽出战（移除野外冒险的妖兽选择入口，UI 文案同步删除"可出战"）。
- **边界**：
  - 副本构建入口本就不允许妖兽出战（不动）。
  - 妖兽不引入技能池/熟练度/专长/容量体系——直接攻击无熟练度成长，维持"妖兽资质随机、无专长之途"的定位。
  - 妖兽出战的其他战斗行为（面板/受击回能/结果弹框）不动。
- **实现提示**：`wildSpirit()` 妖兽分支 `skills` 由 `[]` 改为 `directUnlocked(elem, lvl||1)` 返回的 def 列表（元素为 SKILLS 池内对象，renderBattle 现有 def 解析天然可查）。

### P0-2 野外战斗技能编辑器即时生效（双引擎统一）

- **现状**：`battleSkill` 技能解析与 `renderBattle` 卡片 def 解析均用 `Object.values(SKILLS).flat().find(x=>x.id===skId)` 查原池，不查 `S.skillEdits`（只有 `skillById()` 查，但战斗引擎未用）。
- **方案**：野外战斗引擎的技能解析统一改用 `skillById()`（含 `S.skillEdits` 覆盖）：
  1. `battleSkill` 内的技能 def 查找改为 `skillById(skId)`；
  2. `renderBattle` 技能卡片的 def 解析改为 `skillById(sk.id)`（编辑/自定义技能卡片不再显示"—"）。
- **边界**：
  - 副本引擎 `dgSkillDef` 已含 skillEdits，不动（回归对象）。
  - 机制技（regen 等 universal 技能）走同一路径，不受影响。
  - `skillUsable` 使用解析后的 def（编辑后能耗/能量门槛随之生效）。
  - 编辑器新增的自定义技能：野外战斗中可用（此前为"点击静默无反应"）。

### P0-3 野外遭遇妖兽策略恢复（安抚/战斗/离开/突袭 + 被突袭应战）

- **现状**：`moveTo` 遇 fight 事件直接 `startBattle`；`renderWildNode`（正面安抚 40% / 悄悄安抚 60% / 悄悄离开 / 悄悄突袭 / 被突袭应战）整段无调用点；22% 被突袭无"应战"确认界面。
- **交互流（恢复旧设计并适配 grid 事件结构）**：
  1. **boss（template==='boss'）**：不突袭、不弹遭遇卡，直接正面对峙（保持 v1.15.0 决策）。
  2. **被突袭（event.ambush）**：显示「被突袭·应战」卡 → 应战 → `startBattle(beast, 'ambush', buffs)`（敌方先手一击）。
  3. **其他 fight 事件**：显示遭遇节点卡，五选项卡：
     - **正面 · 安抚**：40% 成功 → 免战 + `beastDrops(speciesId,'calm')` 少量掉落；失败 → 进入战斗。
     - **正面 · 战斗**：谁快谁先手。
     - **悄悄 · 离开**：无掉落，回网格，事件格 resolved。
     - **悄悄 · 安抚**：60% 成功 → 免战 + calm 掉落；失败 → 仍暴露，进入战斗。
     - **悄悄 · 突袭**：`startBattle(beast, 'sneak', buffs)`（玩家先手一击）。
  4. 战斗/安抚结束按既有 `wildNodeDone` 标记事件格 resolved。
- **实现提示**：`moveTo` fight 分支改为三分支（boss 直战 / ambush 弹卡 / 其他弹五选项卡，`w.phase='node'`）；`renderWild` 分派增加 node 分支复用 `renderWildNode`；`renderWildNode` 内按钮适配 `c.event` 结构（beast/buffs/ambush/template）。
- **参考案例**：宝可梦野遇菜单（对战/逃跑的决策感）；本作 v1.13 前旧遭遇节点 UI 的既有实现。

### P0-4 战斗捕捉点亮图鉴

- **现状**：结果弹框「捕捉·留它活口」成功分支直接 `S.beasts.push({...})`，未调 `markDexSeen`；该函数仅在 makeBeast/evolveSpirit/landSpirit/init 被调用。
- **方案**：捕捉成功分支补 `markDexSeen(b.beast.speciesId)`（或改为经 makeBeast 构建并保留 `caught:'地图名 · 活捉'` 文案，二选一由开发按最小改动定）。
- **边界**：捕捉失败（宁死不从）不点亮；重复捕捉同物种不报错、不重复计数；异色捕捉沿用现有 shiny 判定（点亮逻辑与普通捕捉一致）。

## 四、验收标准

> 每条可观测、可断言；测试者按此逐条验收。括号内为断言要点。

**P0-1 妖兽出战**
1. 选妖兽出战进入野外战斗：技能栏含 ≥1 张直接攻击卡（属性=妖兽属性、含威力/能耗/类型）+「回能」卡。（renderBattle 技能卡数量 ≥2）
2. 循环点直接攻击卡：敌方血量下降；普通 1v1 战斗可获胜（`phase==='won'`）。
3. 副本构建界面仍不可选妖兽（入口不变）。
4. 灵兽出战零回归：技能栏 = 原技能 + 回能，数量/行为不变。

**P0-2 编辑器即时生效**
5. 编辑器将某技能 power 改为 999 → 野外战斗释放该技能伤害显著提升（> 原版数值）。
6. 编辑器新增自定义攻击技能并装配 → 野外战斗技能栏显示该卡（非"—"）且点击生效（敌方掉血且有日志）。
7. 副本战斗使用同一编辑技能，伤害与编辑前一致（dgSkillDef 路径不回归）。

**P0-3 遭遇策略**
8. 遇非 boss 妖兽（非被突袭）→ 出现五选项卡（正面安抚/正面战斗/悄悄离开/悄悄安抚/悄悄突袭）。
9. 正面安抚成功 → 免战 + calm 掉落、回网格、事件格 resolved；失败 → 进入战斗。
10. 悄悄安抚成功 → 免战 + calm 掉落；失败 → 进入战斗（无先手）。
11. 悄悄突袭 → 战斗以玩家先手一击开始（`hitBeast` 生效）。
12. 悄悄离开 → 无掉落、回网格、事件格 resolved。
13. 被突袭事件 → 显示「被突袭·应战」卡；应战后战斗以敌方先手一击开始（`hitSelf` 生效）。
14. boss 事件 → 直接正面对峙战斗，不弹遭遇卡。

**P0-4 捕捉点亮图鉴**
15. 捕捉一只图鉴未点亮的物种成功 → 图鉴该物种点亮（`dexSeen` 含该 speciesId）。
16. 重复捕捉同物种不报错；捕捉失败不点亮。
17. 回归：damage / wild / mech / v1192 / v1195 套件全绿；本次不得新增过期断言，发现的过期断言列入清理清单。

## 五、已拍板决策（2026-09-21 产品总监拍板）

1. **P0-1 妖兽出战方案 → 方案 A**：妖兽补直接攻击，沿用 `directUnlocked`。方案 B（禁止妖兽出战）作废。
2. **妖兽直接攻击解锁曲线 → 沿用** `directUnlocked(elem, lvl)`，不另设专属曲线。
3. **安抚掉落数值 → 先用默认数据**：沿用现有 `beastDrops(speciesId,'calm')`（30% 少量），功能先跑通，数值暂不调整。
4. **被突袭/突袭先手一击 → 沿用逻辑**：`startBattle('ambush'/'sneak')`，无新设计。

**拍板补充的实现提示（开发必读）**
5. 妖兽技能卡容量显示：妖兽无容量/亲和力体系，`renderBattle` 技能卡「占容」字段对妖兽会算出空值——妖兽出战时不显示「占容」（或显示"—"），避免脏显示。
6. 安抚掉落验收口径：按 `beastDrops('calm')` 实际返回值断言（「掉落 = 现有 calm 逻辑数量」），不写死具体数值。

> 以上决策即最终范围；开发按「需求详情」实现、按「验收标准」验收，不再需要自行判断待拍板项。
