# 需求文档 M3-2 补丁 b · P1 收尾

> 版本：v1.0 | 日期：2026-09-22 | 性质：M3-2 补丁 b（P1 问题整合）
> 前置：v1.20.7（M3-2 补丁 a + 跑偏项修复已封板）；本文档承接产品核查发现的 12 项 P1 问题，全部在本补丁闭环。

---

## 一、需求背景与目标

M3-2 主需求（战斗演出 UI 改造 + 两份动画补丁）已上线，但产品核查发现 12 项 P1 问题：**已设计未接线**（演出/UI 缺口）、**双引擎分裂**（野外/副本行为不一致）、**功能与逻辑未落地**。共同点是"功能存在但不完整或不一致"，影响战斗体验完整性与收集闭环。

**目标**：12 项全部修复；核心方向——**战斗 UI 收敛为一套通用渲染**（野外/副本/事件链共用），一次演出修复双端生效；零新数值膨胀（素材品质为既有品质分层的解锁，不新建素材）。

---

## 二、需求详情

### A 组 · 战斗演出收尾（恢复 M3-2 既定设计）

#### A1 出招名片（恢复既定设计 §3.3）
- **现状**：技能释放时无任何"出招"演出，无相关 CSS/JS（仅日志文案）。
- **方案**：按既定设计接线——我方出招名片 = 技能名 + 右侧克制图标（→）；敌方 = 左侧克制图标（←）+ 技能名；位置：我方展示板右侧/战斗场地左侧，敌方展示板左侧/战斗场地右侧。释放技能时浮现，短暂停留后淡出。
- **边界**：技能名取 `skillById(skId).name`；克制图标复用技能卡已有的克制判定（克制↑/正常→/抵抗↓）。

#### A2 血条 hover 数值（恢复既定设计 §3.2）
- **现状**：`.hp-bar` 无 hover 数值，玩家只能看百分比估血量。
- **方案**：我方血条 hover 显示具体数值（如 `120/150`）；**敌方血条不显示**（既定设计：敌方保持未知感）。
- **边界**：hover 层用 tooltip 或 title 属性均可；仅我方。

#### A3 战斗日志最新在上
- **现状**：`b.log` push 追加、渲染时按数组顺序展示，最新在底部；玩家需滚到底部看刚发生的事。
- **方案**：日志渲染倒序——最新一条在最顶部。
- **边界**：不改变 `b.log` 数据结构（仍 push 追加），仅渲染层倒序；v1.20.7 R1 的 `unshift` warn 开场日志逻辑需同步调整（避免与倒序冲突）。

#### A4 展示板血量数值（恢复既定设计 §3.1）
- **现状**：野外新布局血条仅百分比宽度+刻度线，无数字；副本旧布局反而有数字（`120/150`）。
- **方案**：左右展示板状态栏补血量数字（与等级/能量并列），格式 `当前/上限`。
- **边界**：敌我双方都显示数字（与 A2 敌方血条不 hover 不冲突——展示板数字常驻、血条 hover 是我方专属）。

#### A5 战斗动画接线（恢复两份动画补丁既定设计）
- **现状**：CSS 类已备但 JS 零触发——`.bt-fighter.lunge-left/right`（前冲）、`.bt-fighter.hit`（受击闪红震动）、`.bt-dmg-num`（伤害飘字）、状态图标 popIn。
- **方案**：按既定动画设计接线：
  1. **攻击前冲**：技能命中时攻击方精灵向对方方向冲一下（0.3s）再回原位；
  2. **受击**：被击方闪红 + 左右震动 0.2s；
  3. **伤害飘字**：伤害结算后从受击精灵位置向上飘，0.8s 消失；暴击放大+红色+震动，治疗绿色；
  4. **属性粒子**：释放技能时按技能属性在战斗场地生成粒子（火=红扩散/水=蓝下落/草=绿叶/雷=黄闪/冰=白雪花/暗=紫烟），Canvas 10~20 粒、0.5~1s 消失；
  5. **状态图标弹出**：获得新状态图标弹出（0→1.2→1），消失时缩小。
- **边界**：纯代码动画，不引入美术资源；全部动画总时长 ≤1.5s，不拖沓。

### B 组 · 战斗 UI 通用化（合并渲染层）

#### B1 战斗渲染通用引擎（核心：野外/副本共用一套 UI）
- **现状**：野外战斗用 `renderBattle`（bt- 新布局：立绘/场地/技能卡/功能栏）；副本战斗用另一套渲染（L4449-4475，bp- 旧布局：左右文字属性列+日志流）。两套渲染代码、两种战斗体验。
- **方案**：把 `renderBattle` 改造为**接受战斗对象+上下文参数**的通用渲染函数，野外/副本/事件链共用同一套 UI。
  1. 渲染入参：战斗对象 + 上下文标记（来源=野外/副本/事件链）；
  2. 数据适配：出战方（wildSpirit / 副本 build）、技能解析（野外 skillById / 副本 dgSkillDef，两者均已读 skillEdits）由调用方准备好 def，渲染层不关心来源；
  3. **结算出口按上下文回调**：野外打完 → wildNodeDone/battleResultModal；副本打完 → dgResultModal（多场连胜/通关）；
  4. 副本原 bp- 旧布局渲染废弃，统一走新 UI。
- **边界**：不改变战斗规则与数值，仅统一渲染层；副本多场连胜、队列、常驻增益通过入参传入渲染。

#### B2 副本能耗统一 effEnergy
- **现状**：副本技能结算（L4082-4083）只减 `costdown`，未计入 `energyUp/energyDown`；野外（L5900）用 `effEnergy`（含修正）——双引擎分裂。
- **方案**：副本结算能耗改用 `effEnergy` 口径（含 energyUp 加耗 / energyDown 减耗 / costdown），与野外一致。
- **边界**：`effEnergy` 计算逻辑（L5727-5728）已有，副本直接复用；副本特有 dgBuffSum('swift') 保留叠加。

#### B3 副本敌方能量显示动态化
- **现状**：副本敌方能量显示硬编码 `/20`（L4470-4471），但引擎 `beastEnergyMax:10`。
- **方案**：改为按 `beastEnergyMax` 动态显示（`X/10`），能量条宽度同步。
- **边界**：B1 通用渲染后此项自然随副本接入新 UI 修正。

### C 组 · 功能补齐与逻辑修正

#### C1 普通战斗逃跑（恢复既定设计 §3.6）
- **现状**：功能栏「跑」按钮 `showFlee` 仅 `phase!=='fight'` 时重开结果弹框；战斗中点击零反馈（死按钮）。普通战斗无逃跑；仅 boss 战有技能区逃跑卡。
- **方案**：按既定设计"点逃跑直接触发"——普通战斗开放逃跑：退回上一格、事件格**保留不 resolved**（避免刷取），与 boss 逃跑行为一致。
- **边界**：逃跑不获得奖励；逃跑后该事件格仍可再次触发。

#### C2 背包栏 UI 框架（恢复既定设计 §3.7）
- **现状**：战斗中背包 tab 仅显示"背包（本版本暂不可用）"占位。
- **方案**：补真实 UI 框架——背包物品列表（从 toolInv 读取）、空态提示、基础使用入口。
- **边界**：本次**不新做道具数值/效果**；道具使用逻辑若未建，按钮置灰并标注"功能筹备中"。

#### C3 素材品质解锁（精英/首领模板扩展掉落范围）
- **现状**：每个精灵的掉落 list（`dropsOf`）已含多品质素材（QUALITY_RANK 六档）；但击杀结算走 `upMatFor`（L4654）是空壳——精英/首领怪击杀掉的素材和普通怪完全一样，品质升级未生效。
- **方案**：击杀结算按 template 扩展掉落池品质范围——
  - **普通模板**：掉落 list 中基础品质素材；
  - **精英模板（elite）**：在基础之上**解锁 +1 品质**素材进入掉落池（额外奖励，不筛掉基础）；
  - **首领模板（boss）**：基础 + 解锁 +2 品质素材进入掉落池。
  - 按 QUALITY_RANK 过滤/扩展，不新建素材、不改素材 id。
- **边界**：是**增加奖励范围**（精英/首领多掉一档好素材），不是"筛掉差素材"；calm/捕捉失败的既有掉落逻辑不动。

#### C4 事件链 check 判定读实际属性
- **现状**：`eventStatPanel`（L4555-4563）接收 `stat` 参数但**完全不使用**——不管 check 要判定哪个属性，都用种族公式算"理论面板"，且不读取出战精灵实际属性；events.js 数据明确有 `check:{stat:'spe'...}`。
- **方案**：按 `stat` 取**出战精灵该属性的实际面板值**对比阈值（如 stat='spe' → 取当前出战精灵速度）。
- **边界**：lvlRef（max/mid/number）的挑战等级口径保留；仅把"理论种族面板"换成"出战精灵实际面板"。

## 四、验收标准

> 每条可观测、可断言；测试者按此逐条验收。

**A 组 演出收尾**
1. 释放技能时：我方出招名片显示"技能名+右克制图标"，敌方显示"左克制图标+技能名"，短暂浮现后淡出。
2. 我方血条 hover 出现具体数值（当前/上限）；敌方血条 hover 无数值。
3. 战斗日志最新一条在最顶部（刚发生的事一眼可见）。
4. 左右展示板状态栏常驻血量数字（当前/上限）。
5. 攻击命中：攻击方前冲 0.3s 回位、受击方闪红震动 0.2s、伤害数字上飘 0.8s（暴击红放大、治疗绿）、按技能属性出粒子、状态图标弹出。

**B 组 通用化**
6. 野外战斗与副本战斗渲染为同一套 UI（立绘/场地/技能卡/功能栏一致）；副本不再出现 bp- 旧布局。
7. 副本带 energyUp 状态释放技能，能耗 = 技能能耗 + energyUp（与野外一致）；energyDown 减耗生效。
8. 副本敌方能量显示 `X/10`（非硬编码 /20），能量条宽度与 10 对齐。

**C 组 功能补齐**
9. 普通战斗中点功能栏「跑」→ 退回上一格、事件格保留未 resolved、无奖励；战斗中点击有实际反馈（不再无反应）。
10. 战斗中背包 tab 显示真实物品列表（空态/有物态）；不新做道具数值。
11. 击杀 elite 模板怪：掉落素材含比普通怪高一档品质的素材；击杀 boss：含两档；普通怪不含高档素材。（按 QUALITY_RANK 断言）
12. 事件链 check（stat='spe'）判定取出战精灵实际速度面板；改 stat 后判定值随之变化。

**回归**
13. damage / wild / mech / v1192 / v1195 五套件全绿；野外/副本双引擎行为一致；旧回归基线（v1.20.7 记录的 12 套过期断言）不在本次处理范围。

## 五、已拍板决策（2026-09-22 产品总监拍板）

1. **日志顺序**：最新在上。
2. **普通战斗逃跑**：开放，退回上一格、事件格保留不 resolved（避免刷取）。
3. **背包范围**：本次先补真实 UI 框架（列表+空态+基础使用），不新做道具数值。
4. **战斗 UI**：收敛为一套通用渲染引擎（野外/副本/事件链共用），副本接入同一套 UI（不另写副本专属布局）。
5. **素材品质锁**：elite 模板击杀在基础掉落之上**解锁 +1 品质素材进掉落池**、boss 解锁 +2 品质——是**增加奖励范围**（不筛掉基础素材），不新建素材表。
6. **事件链 check**：改读出战精灵实际 stat 面板对比。

> 以上即最终范围；开发按「需求详情」实现、按「验收标准」验收，无脑补空间。
